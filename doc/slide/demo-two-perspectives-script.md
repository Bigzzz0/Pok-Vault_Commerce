## วิธีควบคุมจังหวะ

ใช้ `run-demo.ps1` โหมด manual เป็นหลัก ผู้ควบคุมกดปุ่มเล็กด้านล่างขวาเมื่อผู้พูดจบแต่ละ cue ถ้าเปลี่ยน browser แล้วหน้าต่างใหม่ยังไม่อยู่หน้าสุด ให้เลือกหน้าต่างที่ถูกต้องก่อนพูดต่อ โหมด timed ใช้ซ้อม/อัดสำรอง ความเร็วปกติหยุดรวม 156 วินาที ปัจจุบันค่าเริ่มต้น Speed=1.5 หยุดรวม 104 วินาที โดยเวลาโหลดหน้าเพิ่มจากนั้น ถ้าพูดบทเต็มตารางให้ใช้ manual หรือ -Speed 1

อย่าอ่านทุกช่องบนจอ พูดผลธุรกิจหนึ่งประโยคแล้วเชื่อมกับหลักการที่นำเสนอไป เช่น Strategy ตอนยอดสุทธิ, Inventory ตอนเลือกบัญชี และ State ตอนสถานะเปลี่ยน

## แผนเมื่อมีปัญหา

- **เว็บโหลดช้า:** “ระบบกำลังอ่านข้อมูลจากเซิร์ฟเวอร์ครับ” รอผลจริง หากกินเวลาเผื่อให้ใช้วิดีโอสำรองที่ซ้อมไว้
- **จอง timeout:** ดูคำสั่งซื้อของฉันก่อน ห้ามจองซ้ำทันที ใช้ชื่อในเกม Demo-<epoch> แยกรอบ
- **ไม่มีบัญชี READY/สต็อก:** หยุดเตรียมข้อมูลให้พร้อมก่อนนำเสนอ ไม่เปลี่ยนข้อมูลเพื่อแสร้งว่า flow ผ่าน
- **ออเดอร์เสร็จอัตโนมัติ:** ไปประวัติลูกค้าได้เลย ไม่กด complete ซ้ำ
- **ถูกถาม Robot คืออะไร:** “Robot ช่วยกดหน้าเว็บและตรวจผลซ้ำได้ครับ ส่วนการตรวจข้อมูล ส่วนลด สต็อก และสถานะยังทำโดย Spring Boot จริง และใช้สอง session แยกสิทธิ์ลูกค้ากับร้านครับ”

## ความเชื่อมโยงกับสไลด์

- หน้า 3 Use Case: CUSTOMER จอง/ดูของตนเอง, STAFF จัดการงานร้าน
- หน้า 8 ER: Order เชื่อม User, OrderItem เชื่อม Inventory และ AssignedAccount
- หน้า 12 Strategy: อ่าน tier จริงจาก profile และคิดส่วนลดหลังยืนยัน
- หน้า 13–14 State: PAID, SHIPPING และ COMPLETED พร้อมเงื่อนไขของ item
- หน้า 17 Sequence: ผู้ใช้เรียกผ่าน UI, Controller และ Service
- หน้า 20 Testing: Robot เป็นหลักฐาน UI เพิ่มเติม แยกจากผล JUnit ที่รายงานไว้
